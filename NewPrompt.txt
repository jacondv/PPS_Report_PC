# Tunnel Concrete Thickness Analyzer

## Project Overview

Tunnel Concrete Thickness Analyzer is a desktop application for analyzing sprayed concrete thickness using point cloud comparison results.

The application loads point clouds in PLY format containing per-point thickness values stored as scalar fields in [distances] filed.

The software provides interactive 3D visualization, region selection, statistical analysis, and PDF report generation.

The application runs completely offline.

## Color Mapping

Users can customize the color palette, selecting the corresponding colors and thickness ranges.
Default: 
Distances < "target_thickness" - "tolerance" is red
Distances > "target_thickness" + "tolerance" is blue
"target_thickness" - "tolerance" < Distances < "target_thickness" + "tolerance" is green
Distances > 150 is light blue.
User can customs color and distance.

Allow user to modify

- Minimum value
- Maximum value
- Invert colors

# Coding Rules

General

- Use C++20.
- Use Qt6.
- Use CMake.
- Follow SOLID principles.
- Follow Single Responsibility Principle.
- Prefer composition over inheritance.
- Keep code simple and readable.
- Avoid duplicated code.

Memory

- Never use raw new/delete.
- Prefer std::unique_ptr.
- Use std::shared_ptr only when ownership is shared.

Headers

- Keep includes minimal.
- Use forward declarations whenever possible.
- Never use "using namespace" inside headers.

Classes

- One class = one responsibility.
- Keep classes under approximately 500 lines when possible.

Functions

- One function = one responsibility.
- Keep functions under approximately 50 lines when possible.
- Avoid deep nesting.
- Extract helper functions when needed.

Naming

Classes

PascalCase

Example

PointCloud
Viewer3D
PolygonTool

Functions

camelCase

Example

loadFile()
calculateVolume()
updateRenderer()

Variables

camelCase

Constants

kDefaultPointSize

Comments

- Explain WHY.
- Do not explain obvious code.

Logging

- Use one logging system.
- Do not use printf().
- Do not use std::cout.

Error Handling

- Never fail silently.
- Return meaningful error information.
- Throw exceptions only for unrecoverable errors.
